# Administrative Operations

The raw `admin:listTable`, `admin:countTable`, and `admin:getAllCounts` queries
and `admin:deleteRecord` and `admin:clearTable` mutations are internal Convex
functions. Ordinary SDK and Convex clients cannot invoke them, including clients
that supply a tenant ID, role, or an `admin` argument. Application auth context is
not deployment administration authority. Their names and validators are retained
for deliberate deployment maintenance; namespaced SDK APIs are unchanged.

This source change protects newly deployed backend code. Existing deployed
backends remain unchanged until their owners deploy the updated source through
a separately authorized deployment. Updating a local SDK package alone does not
update a remote backend.

## Deliberate deployment maintenance

Use the project-installed native Convex CLI, with its deployment-native
administrator credentials and an explicit verified target. First verify the
project, deployment identity, and ownership. Keep credentials out of source,
command arguments, and logs. Never select a maintenance target implicitly from
an existing `.env.local` or a convenient URL.

For an owned disposable target, a non-mutating diagnostic is:

```sh
./node_modules/.bin/convex run --env-file /absolute/path/to/verified-target.env admin:getAllCounts '{}'
```

The environment file must belong to that target and contain the appropriate
native deployment configuration. Keep it private and outside version control.
Convex's authenticated native invocation can call internal functions; ordinary
application clients cannot. Counts use the existing 10,000-record per-table cap
and cover only the tables declared in `admin.ts`; they are not a complete
snapshot or an exact count of larger tables.

Prefer scoped SDK deletion of test-owned resources. For deployment snapshots,
use native ZIP export/import with the selected deployment and inspect the native
import replacement options before deliberate restoration. Internal raw mutations
bypass application scoping and remain powerful deployment maintenance tools.

## Retired maintenance scripts

`scripts/cleanup-test-data.ts` and `scripts/test-memory-openai-20x.mjs` exit
nonzero before reading environment files, opening clients, running tests,
deploying functions, or deleting data. Supplied URLs, flags, and credentials do
not re-enable them.

Replace blanket sweeps with unique test-owned resources and scoped SDK cleanup,
or recreate a verified disposable deployment. Repeated managed embedding tests
require a separately provisioned disposable managed target and appropriate LLM
credentials. A passing local boundary check does not certify managed or LLM
coverage.
