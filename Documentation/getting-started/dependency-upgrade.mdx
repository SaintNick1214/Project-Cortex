# Dependency upgrade verification

The TypeScript SDK, CLI, Vercel AI provider, and all three CLI demo templates were refreshed against the npm registry on October 2, 2026. The Python SDK and its legacy cross-language pipeline scripts are preserved in `_DEPRECATED/`; active CI and publishing now cover the TypeScript packages.

## Runtime and compatibility

Use Node.js 24.15 or newer and npm 12.2.0. `.nvmrc` selects Node 24. Each source demo has its own lockfile and uses local SDK/provider links so it exercises this checkout. CLI scaffolding replaces these links with the SDK version from the package being distributed.

Release the updated SDK, provider, and CLI together when publishing these changes. The previously published SDK's OpenAI peer range stops at v6; the refreshed templates require the updated SDK's v7 support.

The refresh includes Convex 1.46.0, OpenAI 7.27.0, Anthropic SDK 0.131.0, AI SDK 7.0.127, Next.js 16.3.8, React 19.3.0, ESLint 10.11.0, Jest 30.5.2, and Vitest 5.0.3. `npm run update-deps:dry` checks all seven active package manifests and excludes the archive.

Two version choices preserve compatibility:

- TypeScript is constrained to `~6.0.3`. The current `ts-jest` peer range excludes TypeScript 7, and TypeScript ESLint supports versions below 6.1. The dependency updater checks patches within this compiler version.
- The chat template uses NextAuth `5.0.0-beta.32`, the latest v5 beta. Its APIs require v5; the registry's stable v4 release would be a downgrade.

The older quickstart runs ESLint directly because Next.js 16 removed `next lint`. Its flat configuration uses the current TypeScript parser and ESLint compatibility wrappers for React rules that still call removed ESLint context methods. Its npm overrides keep the older plugin peer declarations on the verified ESLint 10 version, allowing reproducible clean installs.

The copied Vercel quickstart in the CLI was separately installed from its lockfile, built, and passed its 80 unit/integration tests. SDK/provider/CLI builds, both production web builds, demo development startup, CLI scaffolding, and CLI database statistics succeeded. Streamed responses from both web demos completed successfully and persisted conversation history.

The SDK's existing conditional tests skipped 211 cases for optional graph services, managed vector search, and other unavailable service configurations. The CLI skipped four explicitly disabled participant tests. These integrations are not covered by the local verification results.

`npm audit` reported zero vulnerabilities for the workspace and each independent demo install. Type checking and lint commands pass; the SDK retains existing non-failing lint warnings.

## Reproduce from a source checkout

Configure `.env.local` with a working Convex deployment and OpenAI credentials before running integration or end-to-end tests. Deploy the checkout's `convex-dev` functions to that deployment. The default SDK runner recognizes a local `CONVEX_URL`; graph and managed-deployment tests require their additional service configuration.

```bash
npm ci
npm run build
npm run build --workspace @cortexmemory/vercel-ai-provider
npm run build --workspace @cortexmemory/cli
npm test
npm test --workspace @cortexmemory/cli
npm test --workspace @cortexmemory/vercel-ai-provider
```

Install each demo with `npm ci` in its own directory after building the SDK and provider:

- `packages/cortex-cli/templates/basic`: `npm run build`, `npm run test:all`, and `npm run server`. Set `SERVER_URL` when running the HTTP server end-to-end tests against the running server.
- `packages/cortex-cli/templates/chat-sdk-quickstart`: `npm run lint`, `npm test`, `npm run build`, and `npm run test:e2e`. The browser runner starts a development server or reuses the server on `PORT`.
- `packages/vercel-ai-provider/quickstart`: `npm run lint`, `npm test`, and `npm run build`. Run the application with `npm run start`, enable fact extraction with `CORTEX_FACT_EXTRACTION=true`, and run live tests with `QUICKSTART_URL=http://127.0.0.1:3000 npm run test:e2e`.

`npm run dev` starts either web demo for development. Both demos explicitly use Webpack for the verified development and build commands. `npm run start` serves the production build. The CLI prebuild synchronizes the Vercel quickstart into `packages/cortex-cli/templates/vercel-ai-quickstart` while preserving local environment files and installed dependencies.
