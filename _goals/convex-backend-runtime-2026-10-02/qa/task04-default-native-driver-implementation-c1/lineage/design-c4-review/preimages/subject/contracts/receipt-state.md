# Exact receipt and state contract (design, not installed implementation)

All fields below are REQUIRED; null means unavailable, zero means observed zero. Objects have exactly their named own data keys, recursively; no symbols/accessors/prototype/cycles/sparse arrays/ill-formed Unicode/-0/NaN/Infinity. Use accepted C2 canonical.ts descriptor-first detach/sorted-key JSON. Receipt <=8192 UTF8 bytes, graph <=4096 nodes/depth16; string key/values well-formed. Account state <=524288 bytes with same graph bounds (state <=4096 nodes). Larger evidence stays root-private and is represented by digest. No public caller submits receipts or proof labels. The capture boundary revalidates observer classifications using closed proof APIs.

Types: H=lowercase hex64; ID=well-formed nonempty string <=256 UTF8 bytes, no C0/DEL controls; Ref=H (content addressed proof entry, not arbitrary URL); N=integer 0..9007199254740991, no -0. Epoch=N>=1. Time=N (milliseconds UTC). Nullable<T>=T|null. Categories are a sorted unique subset of EXACT enum ["cache-read","cache-write","cancelled","inference","rejected","routing","surcharge"], <=7, no unknown entries; unknown encountered raw categories cause unsupported/STOP and bounded raw digest rather than inventing enum membership.

## Capture/fact union and writes

Capture parses before update. An invalid first/different receipt commits exactly one account STOP/private-close update, preserves K/known/active/earlier terminal, publishes one account-row update once (format version remains2; Convex OCC, no custom counter); if account is already stopped, attachment closed and active/known/reserved require no transition, any repeated malformed capture returns invalid-retained with zero writes. No malformed receipt overwrites accepted facts. No additional diagnostic ledger is introduced. Contradiction to previously accepted immutable facts is CAPTURE_COLLISION with ZERO writes (earlier STOP/charge/closure remain). Dispatcher catches collision, invokes separate idempotent STOP-control mutation if not already stopped; that mutation one write/closed attachment, no reset. This preserves inherited C2 collision rollback semantics without permitting further dispatch after detected provider contradictions.

Immutable nonnullable fields: version/scope/binding/scenario/dispatch/native/expectedWire/method/interface/requestedModel. For nullable observed facts (responseId, actualModel, raw/native finish, counts, observed cost/currency, resultHash, each proof), once present a later receipt MUST resupply equal values; cannot disappear/change. rawDigest references accumulated transcript, so use firstRawDigest + refinementRawDigests as append-only evidence references in Facts; do not require digest equality when a genuine independent dimension upgrade adds raw evidence. In ReceiptV2 rawDigest is immutable per receipt; prior exact receipt remains replayable. Category facts are an immutable complete sorted observed set once nonempty, never narrowed/expanded in refinement; new raw category creates collision/STOP and separate withheld raw evidence. serving/usage classifications cannot change during capture refinements: observer builds these before first capture, otherwise unknown is irrevocable for this attempt. Their proof/null facts cannot appear later without a lifetime/money dimension upgrade and cannot promote serving readiness on their own.

First receipt stored once. Later exact any historical canonical replay => zero writes. A new receipt requires lifetimeUpgrade (unknown->validated terminal and !released) OR moneyUpgrade (unknown->validated full amount and known=null), max2 refinements. Null facts may fill ONLY alongside one of those independent upgrades, never fact-only. Lifetime/money can't downgrade; a receipt stating unknown after established validated dimension is interpreted as absence of NEW proof only if it resupplies all established observations/proof fields and fold retains known dimension; cross-field parser therefore receives accumulated prior context and validates effective classification, not erasing it. Simpler implementation choice frozen here: later receipt MUST resupply established validated classifications/proofs/amount; this avoids ambiguous downgrade syntax and still permits independent money then lifetime/lifetime then money. Thus full retained known charge stays explicit on later lifetime upgrade. Both upgrades together consume one refinement; third or no-upgrade => collision0writes.

A first unsupported/unknown receipt commits retained liability and STOP, closes attachment permanently. A later permitted proof refinement can settle/release but never clears STOP/reopens private data. A validated terminal releases only its own active slot once; qualified money replaces fullK with full known amount once, never clips >K. Full known on drift requires independent money proof covering exact drift actualModel. Unknown lifetime leaves active even if money known. Unknown money leaves K even if terminal releases slot. All writes use same account-row OCC transaction; no new permit while stopped/active. v1 unchanged nonpaid scope is always denied by v2 parser and v2 denied by original v1 parser.

## Normative parser order

1. Decode JSON with duplicate-object-key rejection; enforce UTF8 byte bound BEFORE parse. Run descriptor-first own-data graph validator, then sorted-key canonical equality to original text. Count nodes/depth and reject sparse/accessor/symbol/proxy-untrusted boundaries as inherited Convex plain-data constraints; never invoke getters.
2. Exact top-level/nested Binding/Counts keys; check enums and N/Epoch/H/ID/null types (boolean never integer); all IDs/strings scalar Unicode and byte bounds. Check category ordering/uniqueness/finite enums; result/proof/digest hashes exact. Version2 scope exact, never infer version from keys. State firstCapture/refinements strings each reenter same receipt parser.
3. Resolve scenario from fixed compiled14 and compare binding/case native/wire/method/interface/model/dispatch against checkpoint; validate counts against c.inputU/maximumOutputM whenever supplied, even if classification unknown. Any overbound becomes retained-invalid STOP, not an accepted unqualified fact hidden from bounds. Result size checked separately against c.conditionalPrivateMaximumBytes; raw evidence byte digest does not establish that bound.
4. Apply complete cross-field matrix above; known amounts require exact decimal rational ceil equality and supported monetary resolver result. State parser recomputes Facts fold/arithmetic/slot owner from immutable accepted receipt sequence; no trusting stored flags/classification. For actual capture, load private transcript and rerun reducer/resolver; a syntactically qualified label with EMPTY/unknown resolver is downgraded to unknown receipt BEFORE storage, removing moneyProof/microUSD and lifetime/serving proof classifications, reason missing-evidence. Preserve observed amounts separately. A false caller label never triggers charge/release. If no prior receipts, publication is conservative STOP1write; if supplied downgrade contradicts prior trusted facts, collision0writes then STOP-control.
5. Union compare before writes; exact canonical historic receipt replay returns0writes before current result-authority checks, but not before immutable dispatch binding. A now-revoked grant does not discard already recorded charge or reopen attachment. Contradictions return collision, not rollback-plus-new-attempt. Invalid integer aggregate arithmetic overflow is STOP/unknown full liability diagnostic; never clamp, wrap or reset. Amounts beyond safe integer representability remain observed decimal/unqualified (unknown money/fullK), not invented known0. Reviewed extension to larger accounting representation would require independent gate.
