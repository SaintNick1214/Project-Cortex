# Public fact-history maintenance safety bridge

Scope: fresh-install runtime Task03 foundation maintenance. Frozen 03A classifies `factHistory:logEvent`, `deleteByFactId`, `deleteByUserId`, `deleteByMemorySpace`, and `purgeOldEvents` as internal backend operations. Their public SDK entry points (`log` and the four identically named maintenance methods) preserve their existing TypeScript signatures but always reject before any query, mutation, action, or resilience execution.

The rejection is `FactHistoryCapabilityError`, exported only from `src/facts/history.ts`. It has `version: 1`, `code: "CAPABILITY_UNAVAILABLE"`, `retryable: false`, and `outcome: "not_dispatched"`. Its static message is "Fact history writes and maintenance require trusted backend execution. No operation was dispatched by this client." The error carries no selectors, input values, actor labels, private metadata, cause, function reference, event ID, or deletion statistics. It never indicates a successful write or deletion. Applications can inspect these fields on the rejected error without importing backend-only modules.

Every call rejects, including empty selectors, invalid retention dates, omitted optional selectors, and caller properties naming administrators/operators. Caller properties are not hydrated. There were no existing explicit SDK validation rules for these five methods to preserve; retention dates are no longer evaluated because the operation cannot be dispatched. This is an intentional public safe-error contract, not a legacy functional compatibility guarantee. Backend operator authority cannot be forwarded or granted by the browser SDK.

The six existing public reads remain byte-preserved: `getHistory`, `getEvent`, `getChanges`, `countByAction`, `getSupersessionChain`, and `getActivitySummary`. Their public references, date conversion, selectors, resilience behavior, successful return values, and denial propagation remain unchanged. Tests exercise native disabled Convex clients with mocked transports; they certify the client boundary, not live backend authorization or functional history processing.

History writes remain server-owned. Tasks05/08 retain eventual functional history/derived-memory requirements. This temporary unavailability does not complete those features, Task03-final, or prove transcript safety closure. No public alias, internal forwarding, reference cast, alternate writer, or fabricated result has been introduced.
