Result includes stable ledger operation/attempt IDs, reservation/qualification hash, state and permitted dispatch generation. All failure paths before checkpoint may release only proven no-dispatch liability. Process crash after checkpoint is conservative unknown even if no network occurred.
4. `recordTerminal` internal mutation: stable attempt/settlement identity, exact usage/cost provenance/result hash; once-only monetary settlement with qualified complete charge, or known-token/unknown-cost state retaining reserve. Charge bookkeeping remains permitted after revoked authority without private result delivery. Different duplicate receipts conflict; overrun fully recorded and blocks further spend. Currentness checked separately for result retention/reuse/delivery/derived commit.
5. `recordUnknown`/reconcile: sanitized failure category, visible/effect flags, terminal proof distinction and cancellation status. Crash, transport error, malformed terminal, missing charge, postdispatch cancellation or settlement failure never grants a new automatic attempt. Native timeout does not prove upstream stopped or cost zero. Release concurrency only actual terminal proof or independently qualified enforced upstream lifetime; preserve monetary unknown until reliable reconciliation.

These names are interface suggestions for ledger coordination, not permission to create a second ledger or public RPC. All queries/mutations need trusted internal provisioning/registration checks.
