## Findings and concrete recommendation

1. Convex bills at **OpenRouter rates**, not an independently promised OpenAI-direct tariff: [Convex usage and billing](https://docs.convex.dev/ai-gateway/usage-and-billing), “We charge the same rates as OpenRouter.” Pricing varies by model, time and cache. The fetched OpenRouter public model pages presently match the three OpenAI-direct base prices, but matching observations do not establish future fixed Gateway prices or complete receipt coverage.
2. Default embedding can use a conservative **UTF-8 byte upper bound without a new tokenizer dependency** for strings. The official OpenAI guide specifies cl100k_base; official tiktoken educational source starts with individual UTF-8 bytes and only merges. Bound each normalized value<=8192 UTF-8 bytes, batch<=512 values and aggregate<=300000 UTF-8 bytes, plus tighter trusted policy caps. This gives a conservative embedding token upper bound under the documented native BPE/string-input semantics. It needs exact Gateway/profile/transform qualification before readiness, but does not invent hidden message framing. Unknown alias/tokenizer/normalization drift fails closed.
3. Official Chat framing code explicitly says “estimate, not a timeless guarantee”; functions consume extra tokens. No fetched official source gives a rigorous full Chat or Responses hidden-framing upper bound for arbitrary tools/schema. Installing a tokenizer alone does not solve that. A restrictive byte bound on prompt strings also does not bound unknown protocol-added framing. Keep strict predispatch token-proof enforcement unresolved for these native interfaces until a supported proof/qualification is accepted.
4. There is a finite **full-model-envelope monetary candidate**: price the entire documented maximum input context plus the entire documented maximum output at the most expensive applicable input/output rates, instead of pretending the next prompt is known to consume4096 tokens. This is a conservative rate-based reservation for a successful request only if native context/output enforcement, rejected/cancelled-call charge behavior, one-charge/native-call semantics, all charge categories and rate revision are qualified. It does not independently prove a tighter input/context application cap or complete monetary settlement. No candidate is labeled actualcostqualified.
5. Implement the dispatcher/ledger interfaces with a trusted token-bound/price proof seam and empty real-ready bootstrap manifest; qualify the narrow embedding path first. Keep Chat/Responses constructors and all terminal/cancel/unknown accounting implemented/tested, enabling real text admission only after proof and real native qualification. Preserve all eventual tools/structured/extraction capabilities and mapped later gates; this research does not remove them.

## Concrete embedding token-bound algorithm

Normalize text by existing profile NFC/LF contract exactly once; detach/freeze texts sent to native provider, reject malformed inputs before identity, and do not dispatch original mutable strings. Let B_i=TextEncoder.encode(normalizedText_i).byteLength, computed on the final native value. Require nonempty finite-length strings, no hidden per-value providerOptions, no user/dimensions overrides; immutable default profile/model/dimensions1536. Reject malformed Unicode or explicitly canonicalize surrogate replacement under an approved normalization version so byte count and provider tokenizer see identical strings; do not silently change existing profile semantics.

Official tiktoken simple BPE tokenizes each matched word into UTF-8 bytes, creates one initial part per byte, then merges adjacent parts. Thus ordinary string token count<=UTF-8 byte count; special markers handled as ordinary text or validated native literals cannot add more tokens than their byte representation. Embedding docs count input text using cl100k_base and add no Chat role/tool framing. The upper-bound argument applies to the strings actually embedded, not arbitrary JSON byte length, encrypted transport, or model-added prompts. Actual profile/service qualification must confirm Gateway forwards those exact strings and no added prompt prefix.

Validate B_i<=8192 (or a tighter qualified per-value policy), sum B_i<=300000 and count<=512. Batch greedily by both aggregate-byte and count limits before embedMany/native splitting; pin stable ordinal/start/end in child identity. Additional trusted operation/input caps may require smaller aggregate batches. Record inputTokensUpperBound=sum B_i, not an invented measured exact count. Set embedding qualification's aggregate context/request cap consistently, with an independent per-value8192 check; don't compare a300000-token batch sum with a per-value8192 context cap. This is a model-policy/adapter coordination requirement, not permission to loosen other native limits. Current source chunks max1600 code points imply <=6400 UTF-8 bytes for valid Unicode scalar text;512such chunks still need aggregate splitting, rather than pretending count<=512 suffices.

Candidate reservation at0.02USD/1M tokens is ceil(sum B_i /50) microUSD: one byte-upper-bound2048token request41microUSD, maximum aggregate300000token request6000microUSD. Count-only512*8192 could reach4194304tokens and83887microUSD, but that exceeds the documented300000aggregate maximum; reject/split it before service token. Every batch is independently admitted against the same parent+tenant budgets, so splitting cannot evade run quota. Native vectors remain finite1536 and profile-tagged, then actual managed write/search/currentness/auth qualifies readiness before Task09.

No new dependency is needed for this restrictive upper bound. For less conservative embedding limits, the minimum additional component is a Convex-compatible pinned cl100k_base BPE implementation/vocabulary with reviewed correctness parity against official tiktoken and source hashes. OpenAI official tiktoken is Python/Rust, not a verified default-runtime TypeScript package. Community js-tiktoken/gpt-tokenizer is a candidate requiring dependency approval/installation, license/runtime/bundle review and parity qualification; neither is installed nor adopted here. For Chat gpt4o/gpt4.1, official mapping uses o200k_base; tokenizer text counts still exclude undocumented framing, so no tokenizer dependency recommendation can falsely close that gap. Do not call a provider token-count API unless an official Convex-supported native route is separately established and authorized; no such request was made.

Validate actual raw fields without inventing them; complete observed token count plus reviewed full applicable tariff can settle a restricted model if charge rule genuinely covers all categories and pricing revision. Until then retain reservation and recorded known tokens. This research supplies price references/conditional bounds, not a settlement receipt.

Use integer microUSD account arithmetic. Parse reviewed decimal tariffs as exact rationals (BigInt numerator/denominator); sum full categories then ceil outward once per attempt. A price of0.15USD/1M equals0.15microUSD/token, not0.15USD/token. ceil(n/d)=(n+d-1)/d for nonnegative integers. Preserve native raw charge/provenance and ledger units; zero requires qualified actual zero, not missing data. For aggregate dollar receipts, exact decimal lexeme is preferred if supported response access preserves it. Native metadata numbers are IEEE754: validate and use an outward safe conversion/interval (e.g. upper neighboring representable value then exact rational microUSDceil) to avoid binary multiplication rounding below actual charge; never assume floatingpoint number.toString reconstructs an arbitrary original decimal exactly. Overflow/safe integer/currency checks and duplicate receipt identity remain mandatory.
