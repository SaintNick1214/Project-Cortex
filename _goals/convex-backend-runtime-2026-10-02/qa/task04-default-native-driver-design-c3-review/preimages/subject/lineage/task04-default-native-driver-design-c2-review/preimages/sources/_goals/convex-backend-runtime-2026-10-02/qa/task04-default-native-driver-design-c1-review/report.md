## Issues found

### Critical to DESIGN PASS — repairable contract gaps

1. **No exact v2 receipt/validated-state schema.** proposal.md:29–31 enumerates conceptual fields, nullable classifications and “safe bounded” references, but does not define their exact names/types/required keys, enum values for method/interface, identifier/hash/string/reference limits, epoch integer constraints, canonical/graph/receipt-byte limits, category array rules or the cross-field matrix. For example, the receipt can describe validated-whole-invocation-usd yet the amount field and coverage-reference relationship are not frozen; independent raw/mapped counts and finishes have no explicit field schemas. Inherited guard.ts:Observation is v1/nonpaid and cannot provide these rules for added facts. Specify a strict typed v2 schema plus exact parser/cross-field validation and immutable-fact union rules, including unknown versus zero/null, malformed/colliding receipts and STOP publication. Do not just change a scope union or boolean. Provide finite hostile examples with expected committed account, slot, writes and attachment outcomes.

2. **Lifetime and monetary qualification are requirements rather than defined authority APIs.** proposal.md:33 says “genuinely supported ... correlation” and “separately source-reviewed terminal contract”; :31/:35 require complete currency/category/whole-invocation proof; :57 explicitly leaves the source-level terminal validator API NOT_READY. No signature/return contract identifies the observer inputs, exact supported finish choices/ID checks, native/raw count correlation, stream conflict/ordering/final aggregation, or embedding completion rule. No closed proof resolver defines what a monetary/serving reference binds, who installs it, how source revision/expiry/currentness is checked, or how coverage of drift/rejected/cancelled/routing/cache categories is established. Official Chat emits a native finish during flush even when no raw finish was present (compatible Chat:720); embedding native output exposes raw body without validating model/ID in its minimal schema (compatible embedding:173–193). The design must define how these yield unknown versus genuine lifetime. Actual evidence may remain unsupported/unknown; a finite API can return that branch now. Freeze supported accepted-source predicates, their absence/contradiction behavior and exact outward conversion (or pin the reviewed conservativeUsdDecimal plus safe integer conversion). Every known-money branch must require independent complete proof, and every unavailable branch must preserve fullK. A future unspecified official-surface provenance extension must remain a separately reviewed design gate, not an implementation escape hatch.

3. **Managed fixture schema/repository shape and concurrency fences are deferred.** proposal.md:45 permits root to compile “minimal ... controls” while :57 labels interfaces NOT_READY. The inherited schema has only experimentControls; the design names an index but no vector/source/chunk/grant tables, field validators, vectorIndex definition/filter fields, repository method signatures, search limit/result allowlist, E11 idempotency identity or transaction/pre/post-search fence mechanics. Epoch checks stated before/after async work do not freeze which records are reread atomically at commit and before hydrated results return. Specify the standalone owned schema and write/search/read/delete interfaces, exact default profile/index mapping, expected source revision/tombstone/grant checks, E12/E13 no-write outcome and deterministic stale/wrong-tenant/profile denial controls. This is fixture design only and must not import the production root or reuse the old vector schema.

### Important

4. **C09/C10 trigger and result-authority protocol is not specified.** Accepted preparation requires origin revoke/current-owner cancel after the first eligible persisted part; proposal preserves IDs/order but provides only generic abort/revoke/closed-attach rules. Its capture-before-attach, terminal assembly and unknown-money withholding leave unclear which bounded private staging record constitutes that first part, who triggers the control mutation, how the trigger is durable/once-only, what happens if no eligible part arrives, and how cancellation is driven while a reader/RPC is pending. Define that server-owned trigger separately from public delivery and terminal attachment, retain the approved request/hash, and specify no eligible-part/late-trigger/response-loss outcomes. Explicitly test no later private delivery, retained original-account full known/unknown liability and no replay. This is not permission to open partial result authority or relax capture-before-attach.

Deduplicate current references and freeze the exact embedding/raw response schema and relevant provider v4 type sources in the revised design packet. This is evidence hygiene, not evidence of an actual serving mismatch.
