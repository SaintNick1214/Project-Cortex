# Task06 additive backend — offline implementation handoff

Status: author offline source/tests ready. Original Task06 live installation and independent acceptance are pending the accepted Task05 prerequisite. This report does not complete Task06 or the full goal.

The installer no longer moves or replaces the host functions tree. SDK build generates `dist/backend/v1/manifest.json` plus the exact backend TypeScript import closure, a `cortexTablesV1` table map and `registerCortexComponentsV1` helper. Shared source dependencies are vendored under `_cortex/shared`; host bindings remain owned by ordinary Convex codegen. Native runtime directives and function names are retained. Backend schema inspection imports the composed host `schema.ts`, rather than the installation fragment. The previously shipped `convex-dev` package path remains for compatibility; this installer never wholesale-copies it.

`planAdditiveBackendInstallation` resolves the existing custom functions directory and preserves the original Convex configuration bytes. Explicit schema tables/indexes/options, named host components and explicit trusted JWT provider arrays receive additive AST edits. New Cortex providers require an application audience; official inline public JWKS data URIs are supported and private key material is refused. Existing HTTP routes, unrelated functions and unrelated auth providers remain. Table/component/file collisions, dynamic schema spreads and ambiguous configuration produce a digest-named concrete merge proposal containing the host original and candidate content, before any product writes. They are never adopted/reset automatically. Host integration edits use atomic replacement with retained original backups; a partial failure is retried by replanning identical completed files. Changed preimages, source digests, unsafe paths and symbolic links stop installation.

`verifyDisposableDevelopmentTarget` reads official Convex deployment/project metadata and requires the explicitly selected disposable cloud-development identity. The private receipt is verified in-process; forging its public fields does not confer permission. Each bounded CLI operation rechecks the target and requires a `dev:<same-name>|...` key. Registration uses `convex dev --once`; principal provisioning invokes internal `runtimeAuth:provision` as a trusted operator. The helper creates neither projects nor deployments, returns no credentials, removes its private environment file and waits for the owned process to close. Missing auth/bootstrap/core capability produces an actionable error. The full CLI wizard/demo/template UX remains Task15; these helper operations are the Task06 development boundary.
