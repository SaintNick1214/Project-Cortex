# Foreground ingestion scheduling hooks

Implementation-ready ingestion-owned hooks from runtimeIngestionPriority.ts:

- holdForegroundIngestion(ctx: MutationCtx, run: Doc<runtimeRuns>, definition: ForegroundIngestionDefinition): requires ORIGINAL currentRun server results. Root may call after original admission/start classification and before transaction commit; a matching current DB run and original definition hash/agent selector are required. Only V8 relevant/indexed-plus-pending/no requiredStages, queued/running, one canonical input qualifies. Missing/custom/strict/legacy binding returns held:false.
- releaseForegroundIngestion(ctx: MutationCtx, scope: ForegroundIngestionScope, runId: string): scheduling-only; root calls after ordinal0 finishOperation commits terminal complete, and in original response failure/cancel/tool-approval-wait disposition. Repeated release is idempotent. Release can occur after revocation because it authorizes no work; original claims still recheck authority/source.
- promoteForegroundIngestion(ctx: MutationCtx, scope: ForegroundIngestionScope, through: number): root calls before ORIGINAL strict barrier evaluation, using immutable captured ingestion cutoff and trusted snapshot scope. Original current execution/authority/source checks must precede it. Inside the existing version8 start-context/barrier native parent is a suitable seam; V1–V5 Workflow journal bodies/layouts must remain unchanged. It promotes earlier ordinary input events across conversations through that cutoff, without returning source payloads or changing indexed readiness/deadlines.

Literal root callpoint candidates: runs.submitHandler after original run insertion (original definition is available), or ordinary startExecutionV8 after original activeAttempt classification and before scheduler/parent commit; runtimeAgent.finishOperation after original ordinal0 model-complete write; original endInterrupted/interruptDirectV8/cancel retirement callbacks; version8 branch before original contextBarrierHandler evaluation. Root alone owns these integrations; A does not edit Agent/runs/Transcript.

The durable fallback is runtimeIngestionPriority:expireForeground, one internal mutation scheduled atomically with the marker. Deadline is ORIGINAL run.createdAt+5000ms: submit saves its canonical input and creates its run in that same native transaction (Date.now fixed), so this is the original capture clock. Deferral also bounds against each event.createdAt+5000. Neither replay nor any later turn renews it. At deadline, original processStage actions are awakened; every original claim/lease/job/policy/source/grant predicate still executes. Delayed event registration sees the released/expired marker and uses original scheduling.

Scope is deliberately SAME-RUN CANONICAL USER INPUT ONLY. Existing assistant jobs and other ordinary-run jobs are not delayed merely because a newer foreground starts; tenant-wide contention remains outside this bounded repair. Running, attempted, policy-pinned, reserved/UNKNOWN or independently budget-bound stages bypass deferral. Explicit memory.remember/non-Agent/legacy/strict work retains original scheduling. Strict promotion crosses conversations only for these held original input events. At most256 active markers per scope; overflow uses original scheduling. No account mutation, refund, paid retry/preemption, decision cache or context omission is introduced.

Schema adds one scheduling metadata table and one scoped run/native-message/eligibility/sequence index. No native speed/completion acceptance is claimed by source tests. Final source/test hashes and receipts will follow after finite affected checks.
