- `src/memory/index.ts:1249–1269`: the legacy exchange writer supplies user `{userId}` metadata, agent `{}` metadata and `participantId`, then reads `returned.messages[last].id`. The corrected actual SDK routing control observed two operator append calls with those unchanged fields. `convex-dev/cliOperator/conversations.ts:369–433` reads `conversations` and reconciles `messages:[...conversation.messages,message]`; this remains array storage, not Agent canonical rows. This controlled port does not claim native operator lifecycle/OCC validation.
- `src/conversations/index.ts:248–285`: the public wrapper forwards metadata/participantId and returns the backend result directly. **There is no normalization or automatic rehydration.** `convex-dev/conversations.ts:149–158` first enforces current authority and write lock, then refuses every supplied metadata/participantId with `INVALID_INPUT`. Those actual handler denials were observed after authorized unlock, with no append effect.
- Plain managed append succeeds: `runtimeTranscript.ts:466–474` saves through official Agent then registers one `runtimeTranscriptMessages` bridge per native row (`:175–210`). The controlled actual handler had two native message rows, two metadata bridge rows and zero legacy conversation rows. That supports the correct canonical storage claim. The arbitrary historical `Message.metadata`/participant label is not preserved by this path.
- `conversations.ts:25–31` deliberately returns `messages:[]`. The actual wrapper observed this even after successful append, so an existing caller expecting the appended ID from `messages[last]` cannot succeed. A separate authorized `ConversationsAPI.get` rehydrates the history through `history()`; the probe observed both rows and the requested legacy message ID. This is an explicit extra read, not a wrapper repair.
- `runtimeMemory.ts:201–210` offers a backend-owned **single text/explicit source** remember action with budget/lineage and shared domain services. It is not the two-message conversation exchange API. `src/client-runtime/client.ts` exposes recall/profile/readiness, but no `remember` method. A working Agent turn automatically captures its canonical input/output and ingestion; that different entry path does not establish the requested default remember API.
