    - paragraph: Cortex derives memory from the canonical executable transcript and other eligible retained sources. The backend owns extraction, fact resolution, summaries, chunking, embedding and optional graph projection. Your UI submits a turn and observes its run.

      - code: memoryStatus
      - text: and
      - code: graphStatus
      - text: report asynchronous stages. A completed response can have pending or failed indexing. Render each status independently rather than keeping a response spinner open until all work finishes.
    - paragraph: Facts, canonical chunks and profile-specific vectors retain tenant/space, source revision and hash provenance. Current authority and source versions are checked before context use and publication. An edit or deletion invalidates stale derivations and fences in-flight work.

This allows recent information to participate before indexing catches up. Pending context still obeys source revision, approval, visibility, retention and token bounds.
    - heading "Canonical history and model contextDirect link to Canonical history and model context" [level=2]:
      - text: Canonical history and model context
      - link "Direct link to Canonical history and model context":
        - /url: "#canonical-history-and-model-context"

    - paragraph: The complete canonical transcript is stored as individual message rows, with conversation/order, actor, revision and source metadata. A model request is a bounded selection from that history and memory. Omitting a row from a request does not delete it or prevent authorized history retrieval.
    - paragraph: The new V8 request policy defaults to at most four recent messages, four relevant memory entries and four relevant facts. Required current input and complete tool-call/result groups are retained together. Pending context has a separate four-entry bound and must report incomplete coverage when required evidence cannot fit. Selected facts use existing source relevance and lexical matching; this does not add fact embeddings or another inference call.
    - paragraph: Those counts are maxima. The exact assembled request includes instructions, context wrappers, tool definitions and output reserve, and still passes the published model input/context/cost limits. Optional whole entries are removed to fit; required content that cannot fit fails before a new model call. Full transcript pagination and memory indexing remain separate from this selection. Historical execution versions keep their existing behavior. V8 is a local implementation candidate awaiting service qualification.

    - paragraph: Ordered commits advance a stage's watermark only through consecutive completed events. A later success cannot jump over an earlier pending, failed or missing event. A captured cutoff identifies the point in history required by a consistency check.
