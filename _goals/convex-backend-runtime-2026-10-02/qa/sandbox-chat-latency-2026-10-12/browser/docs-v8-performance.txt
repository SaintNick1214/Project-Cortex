    - heading "Performance and limits" [level=1]
    - paragraph: Cortex separates user-visible response completion from asynchronous memory/graph completion and optional conversation-title work. This avoids coupling response latency to every indexing stage while retaining explicit consistency controls.
    - heading "Bounded workDirect link to Bounded work" [level=2]:
      - text: Bounded work
      - link "Direct link to Bounded work":
        - /url: "#bounded-work"
        - text: "#"
    - paragraph: Published policy bounds input/context/output tokens, tool steps, timeout, budgets and concurrency. Retrieval and transcript reads are paginated/bounded. Strict barriers capture finite cutoffs and configured deadlines; a hole or unavailable stage is an explicit result.
    - paragraph: Runtime client authentication defaults to 10,000 ms; RPC observation defaults to 12,000 ms, configurable within supported bounds. An issued mutation timeout reports uncertainty rather than cancellation/retry. Retain run/job identities for recovery.
    - paragraph: Private upload/delivery is capped at 20,000,000 decoded bytes; providers can impose smaller input limits. Reconnect snapshots retain bounded references rather than copying assets or upstream responses into browser persistence. Asynchronous video generation remains deferred because the official Convex AI Gateway does not support it.

    - paragraph: After governed query embedding, the upcoming private Agent recall path uses a fresh read-plan query, the official Action vector search, and a fresh ordered source-selection query.     - paragraph: The Agent context handler freshly hydrates before its native pending message write; a prepared-data shortcut failed revocation/write ordering and was rejected.     - paragraph: Backend vector and fact retrieval overlap after the original read checks and validated query embedding.     - paragraph: The private Agent query-embedding preflight composes the original authority, profile, readiness, preparation and policy-resolution checks. The next candidate invokes the original profile helper locally in its private preflight and read parents; final delivery retains its profile child query. Admission and the nested dispatch checkpoint share a parent that preserves the reservation if the checkpoint refuses, while rolling back the checkpoint's partial writes. Charge-only capture and private attachment remain separate durable boundaries. Generic public recall and ingestion retain their original preflight. The installed V6 measurements below predate these new read parents; source acceptance alone does not certify latency or tool continuation.
    - paragraph: Private observation combines its initial session and authorized output read in one backend mutation, followed by a separate fresh session check before delivery. The upcoming canonical demo uses the text transport's observation for live run status, approvals and output. After its terminal cursor page drains, a continuing observer protects retained text and tracks later memory status. A failed stream also hands retained text to that guard; disconnect and signout release it. This avoids two concurrent acquisition lanes during ordinary generation. Normal acquisition uses two RPCs; cursor resets and page draining can require further acquisitions. Current principal, scope, protected-source expiry and authentication generation still fence every delivered payload. This observer change requires installed browser qualification.
    - paragraph: Agent model preparation composes the original execution/operation handlers and both policy-resolution checks. Their results propose pinned model inputs; current authorization, qualification, source, transcript and budget controls still run at each billable admission/checkpoint. The outer pre-admission hydration, request binding, admission, parent binding and dispatch checkpoint share one transaction. These changes reduce database handoffs while retaining the current policy, source, lease and budget checks. Their installed latency must be measured separately from source acceptance.
    - paragraph: Selected native queries and mutations reuse raw principal, membership, grant, scope and tombstone records within one atomic invocation. Every authorization predicate still runs, returned records are detached, and database or child-mutation writes invalidate the retained reads. The next invocation reads current records again. Source retrieval, final memory delivery and private output observation retain their original read paths. This scope does not retain permissions, model decisions or authority across a network call or process lifetime.
    - paragraph: Empty-context preparation can also reuse raw deployment-policy and qualification rows within its own transaction. It fetches that metadata again before saving context, and every original policy, qualification and profile check still runs. This reuse does not cross transactions or replace source and delivery checks.
    - paragraph: Selected model-preparation parents also reuse exact raw official Agent message-ID lookups within one invocation. Canonical transcript, current source and authorization checks still run; writes invalidate retained results, and fresh save fences clear them. The installed hosted candidate passed functional qualification, but this does not establish a subsecond response or a controlled speed improvement.
    - paragraph: Fresh installations store compact versioned references to the trusted compiled manifest. New accounts inherit the validated installed root. Existing full records remain supported without rewriting their data or financial history. The runtime still reads and validates current controls. Final memory delivery also shares profile and run-budget initialization for vectors with identical complete profiles and budget identities within one transaction; each vector retains its own authorization, source, chunk, receipt, hash and expiry checks. These changes require hosted measurements before reporting latency improvements.
