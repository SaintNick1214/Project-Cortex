# Parallel vector/fact reads: bounded safety map

**YES for the stated read-only contract**, after every original authority/read-preflight/profile/readiness/embedding-validation step, with both branch settlements owned and vector failure selected before fact failure. **A bare two-line service-only parallelization is not exact bookkeeping/order equivalence** for the Agent adapter; see the concrete difference below. This is a source safety assessment, not frozen implementation acceptance or a speed claim.

The actual [Action repository](/Users/SaintNick/Documents/Cortex/worktrees/backend-runtime-completion/convex-dev/runtimeMemoryRepository.ts:436) searchVectors and listFacts issue authorized native reads/vector search, compute private hashes and capture local consumed-row bindings. Neither invokes a model or writes native rows. Its source dedupe/check/push operations are synchronous; the separate facts/vectors arrays cannot lose updates through JavaScript interleaving. [Agent remember](/Users/SaintNick/Documents/Cortex/worktrees/backend-runtime-completion/convex-dev/runtimeAgent.ts:499) awaits the original contextSource query, then performs witness merge/get/set and provenance set without another await. [mergeContextWitness](/Users/SaintNick/Documents/Cortex/worktrees/backend-runtime-completion/src/domain/context-witness.ts:12) rejects mismatched event/revision/hash and unions permissions in canonical permission order. No lost permission update is introduced by concurrent branch completion. All fresh source/hash/cutoff/per-result checks still execute.

The concrete order difference is insertion order. With serial reads, vector source bindings and Agent witnesses/provenance enter before fact-only sources. Parallel reads can finish facts first. Agent serializes `[...provenance.values()]` into its context and `[...witnesses.values()]` into saveContext ([source](/Users/SaintNick/Documents/Cortex/worktrees/backend-runtime-completion/convex-dev/runtimeAgent.ts:528)); Action finalDelivery scans bindings.sources in captured order. Thus the model context bytes, witness array order and first later consumed-source failure can become completion-dependent even though core recall result assembly remains vector-items followed by fact-items. Existing [context-source-composition test](/Users/SaintNick/Documents/Cortex/worktrees/backend-runtime-completion/tests/unit/runtimeAgent/context-source-composition.test.ts:178) asserts vector-first contextSource calls and ordered witnesses. This is an exact existing assertion affected by the candidate, not proof of a guard bypass.

For unchanged deterministic bookkeeping, stage branch bookkeeping separately and merge vector-then-fact only after both reads complete, while retaining the actual per-result guards. If order is intentionally made unordered, state that material behavior and replace positional assertions with meaningful branch/provenance/permission/identity assertions; do not simply delete ordering coverage or claim original context bytes are unchanged. Preserving only vector-versus-facts promise rejection precedence does not by itself preserve finalDelivery's captured-source error order.

Join both operations using settlement handling that also owns synchronous adapter throws; each operation should be invoked in its own promise task rather than letting argument-array evaluation skip the second call. After both settle, throw the vector error if present, otherwise the fact error. On any failure, do not run finalDelivery or saveContext. Settling the surviving read may delay failure delivery relative to the original serial fast failure; original caller/backend deadlines stay unchanged. This cannot add a billable retry/model call. The generic MemoryRepository interface does not prove arbitrary injected adapters are side-effect-free, so the scope claim is about the inspected production read adapters and regression-tested peers, not every possible adapter implementation.

Required focused regressions in existing groups: runtimeMemory/services (both-start overlap after validated embedding, zero starts on prior guard/embedding failure, exactly one embed, both completion orders, both failures/vector priority, synchronous throws, no orphan late rejection, finalDelivery only after full bindings); runtimeAgent/context-source-composition and context-latency (same ordered result/context, unioned permissions, different source insertion order, conflicting source revision/hash, no context saved on either failure); repository/vector-delivery-batch plus ingestion/context-permissions (fresh final delivery and source/profile/grant/cutoff refusals); existing saveContext races for lease/cancel/transcript/witness/competing save. Preserve the unused-preflight-fact supersession regression and older read-preflight adapter path. No source edits, tests, service calls or paid actions were performed for this map.
