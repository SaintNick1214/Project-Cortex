# TypeScript runtime client

Import `CortexRuntimeClient` and public types from `@cortexmemory/sdk/runtime`. This entry point is browser safe and does not bundle root SDK orchestration, backend functions, graph drivers or model factories.

## Open and observe a run

```ts
import { CortexRuntimeClient, CortexRuntimeError } from '@cortexmemory/sdk/runtime';
import type { RuntimeObservation } from '@cortexmemory/sdk/runtime';

export async function openRun(options: {
  deploymentUrl: string;
  assetHttpUrl: string;
  agentId: string;
  agentVersion: number;
  text: string;
  clientRequestId: string;
  fetchToken: (request: { forceRefreshToken: boolean }) => Promise<string | null>;
  render: (observation: RuntimeObservation) => void;
  clearPrivateViews: () => void;
  onError: (error: unknown) => void;
}) {
  const client = new CortexRuntimeClient({
    deploymentUrl: options.deploymentUrl,
    assetHttpUrl: options.assetHttpUrl,
    fetchToken: options.fetchToken,
    onAuthChange: authenticated => {
      if (!authenticated) options.clearPrivateViews();
    },
  });
  let disconnect = () => {};
  const clearOnAuthorityError = (error: unknown) => {
    if (error instanceof CortexRuntimeError &&
        ['FORBIDDEN', 'UNAUTHENTICATED', 'AUTHORITY_EXPIRED', 'SESSION_CHANGED'].includes(error.code)) {
      options.clearPrivateViews();
    }
  };
  try {
    const { handle, run, start } = await client.submitAndStart({
      version: 1,
      agentId: options.agentId,
      agentVersion: options.agentVersion,
      clientRequestId: options.clientRequestId,
      parts: [{ type: 'text', text: options.text }],
    }, { streaming: true });
    disconnect = client.watchObservation(handle, options.render, error => {
      if (error instanceof CortexRuntimeError &&
          ['FORBIDDEN', 'UNAUTHENTICATED', 'AUTHORITY_EXPIRED', 'SESSION_CHANGED'].includes(error.code)) {
        clearOnAuthorityError(error);
        disconnect();
        void client.close();
      }
      options.onError(error);
    });
    return { client, handle, run, start, disconnect, close: async () => {
      disconnect();
      await client.close();
    } };
  } catch (error) {
    clearOnAuthorityError(error);
    disconnect();
    await client.close();
    throw error;
  }
}
```

The caller generates and retains `clientRequestId` before calling `openRun`, so a lost submit response can be recovered with the same identity. The returned `close()` owns observer/client cleanup; authority errors also clear and close this view. Keep the same request identity for the same semantic intent. `submitAndStart` retains admission and requests execution in one guarded backend transaction; configured input approval still controls whether execution can proceed. The returned `start.state` can report queued or waiting-for-approval work rather than an answer. Never write the returned exchange to memory again.

## Combined admission and recovery

`submitAndStart(request, { streaming: true })` returns `RuntimeAdmissionResult` with `{ handle, run, start }`. Streaming defaults to true. The upcoming client uses two RPCs: `runtimeClient:submitAndStartEnvelope`, which runs the original fresh session check before admission writes, then an independent fresh session read before delivering the result. Omitted scope selectors retain their original ambiguity checks. The client validates the returned actor, scope, authentication generation and delivery expiry against that post-I/O session. The parent mutation preserves the existing admission, approval, queue, authority and immutable-identity guards. The original three-field `runtimeClient:submitAndStart` backend endpoint remains supported. Authentication/connection setup and later observation have additional work.

The legacy `submit`, `start`, `attach` and `get` APIs remain supported for explicit control and recovery. Fresh ordinary V6 starts atomically claim the attempt and schedule one owned Action. Strict memory definitions retain their Workflow stage barriers and deadlines. A completed first-model tool result continues through an additive Workflow for tools, approval and subsequent model ordinals; it does not repeat the first model call. Historical V1–V5 journals retain their execution versions. An initial failure can already be recorded when admission returns, so inspect the returned run and start states. An uncertain issued request can already have admitted or started the run. Stop automatic dispatch, retain the exact original request and `clientRequestId`, and inspect the original run before deciding what to do next. With a known run ID, use `attach` and `get`/observation. If the admission handle was lost, an explicit `submit` of the unchanged original request can recover the original admission identity; it is not a new intent. Do not generate a new request ID or automatically call `start` to recover an unknown execution outcome.

Backend `runtimeAgent:reconcile` can attach the retained completed tool result's missing continuation and return `{ workflowId }`, or recover a final answer and return `{ receiptId }`. This is an explicit recovery operation under the current run authority. It neither retries an uncertain model call nor proves asynchronous ingestion complete. The SDK currently has no run-reconciliation wrapper.

Response completion is distinct from asynchronous memory/graph readiness. Optional conversation-title work is scheduled after canonical answer finalization, so callers do not need to wait for a title to display the answer.

## Methods

| Group | Methods |
| --- | --- |
| Authentication | `session()`, `refreshAuth(fetchToken?)`, `close()` |
| Runs | `submitAndStart(input, { streaming? })`, `submit(input)`, `attach(runId)`, `start(handle, { streaming? })`, `get(handle)`, `cancel(handle)` |
| Observation | `observe(handle, { cursor?, finalOnly?, limit? })`, `watchRun(handle, onUpdate, onError?)`, `watchObservation(handle, onUpdate, onError?, options?)` |
| Approval | `approveInput(handle)`, `approveTool(handle, approval)` |
| Definitions/history | `getDefinition(agentId, version)`, `messages(conversationId, { cursor?, limit? })`, `listConversations(limit?)` |
| Memory | `getEmbeddingProfile(options?)`, `getDefaultProfile()`, `memoryReadiness(options?)`, `recall({ text, requestId, limit? })`, `remember(input)`, `rememberStatus(receiptId)` |
| Content | `submitContentJob(input)`, `getContentJob(jobId)`, `listContentJobs(options?)`, `cancelContentJob(jobId)`, `reconcileContentJob(jobId)`, `applyContentSuggestion(input)` |
| Media/artifacts | `submitMediaJob(input)`, `getMediaJob(jobId)`, `listMediaJobs(options?)`, `cancelMediaJob(jobId)`, `reconcileMediaJob(jobId)`, `getArtifact(artifactId)` |
| Private assets | `uploadAsset(bytesOrBlob, options)`, `getAsset(reference)`, `fetchAsset(reference, options?)`, `createAssetUrl(reference, options?)` |

Private observation acquires a guarded session/output envelope and then obtains a separate fresh session before returning data or invoking a callback. A scope/principal change, expired protected source, reauthentication or disposal suppresses stale delivery. Cached reactive signals carry no private output.

`watchObservation` options include attempt/sequence cursor and final-only projection. Returned disconnect functions affect only the observer. An optional borrowed Convex client remains caller-owned when the runtime client closes.

## Capture an external exchange

The new local candidate's `remember` method captures an independently supplied exchange in the backend. Do not call it to copy an answer already stored by a remote Cortex run.

```ts
import type { CortexRuntimeClient } from '@cortexmemory/sdk/runtime';

export async function captureExchange(client: CortexRuntimeClient, requestId: string) {
  const captured = await client.remember({
    conversationId: 'external-chat-1',
    requestId,
    userMessage: 'I play cello.',
    agentResponse: 'Thanks for telling me.',
    metadata: { channel: 'support' },
  });
  return client.rememberStatus(captured.receiptId);
}
```

Retain the request ID before submitting. Exact replay returns the same receipt and two message IDs; changing an exchange under the same ID is a conflict. The backend verifies identity and current grants, appends individual canonical message rows and schedules its original asynchronous memory pipeline. Metadata does not grant authority, and supplied assistant text is external captured content rather than proof of a Cortex model or tool result.

The receipt includes `messageIds`, `sourceEventIds`, `historyRevision`, `created`, the managed profile, `memoryStatus` and per-message fact/vector stage states. Pending indexing is an actual state; this method does not return fabricated immediate facts or vectors. `rememberStatus` performs fresh receipt/source/profile/authority checks without starting inference. Normal capture appends are separate from manual transcript edits: manual writes remain locked by default, and an administrator can explicitly lock capture appends. Existing Agent conversations keep their original edit/approval rules. These new methods require the matching backend installation. Earlier repeated-capture indexing failures remain recorded. K23 passed capture/replay, native canonical provenance, contiguous indexing, public recall and access/lock/deletion/revocation negatives, all four ordinary chat memory outcomes and the approved tool continuation. The later K24 run again passed the separate capture/recall checks, authentication denial and one approved tool with reconnect/final answer, but warm-chat fact resolution failed and left contiguous facts/vectors through event 2. Its strict barrier correctly returned `CONTEXT_INCOMPLETE`; positive strict readiness was not established. All four K24 latency samples exceeded one second. Historical successes and failures remain preserved.

## Opt-in client latency events

Pass `onLatencyEvent` in `CortexRuntimeClientOptions` to receive scalar diagnostics from the client's monotonic clock. It is disabled when the callback is absent and emits no request arguments, results, prompts, reply text, credentials or error payloads. Keep the callback lightweight; callback failures are ignored.

```ts
import { CortexRuntimeClient, type CortexRuntimeClientOptions,
  type RuntimeLatencyEvent } from '@cortexmemory/sdk/runtime';

export function createTracedClient(options: CortexRuntimeClientOptions) {
  return new CortexRuntimeClient({ ...options,
    onLatencyEvent: (event: RuntimeLatencyEvent) => {
      console.log(JSON.stringify(event));
    },
  });
}
```

```text
RuntimeLatencyEvent {
  version: 1;
  phase: "rpc.begin" | "rpc.end" | "rpc.failed" |
    "auth.begin" | "auth.ready" | "auth.denied" | "watcher.wake";
  atMs: number;
  rpcId?: number;
  method?: string;
  durationMs?: number;
}
```

Use `rpcId` to pair RPC begin/end/failed events; `method` identifies the fixed runtime function. RPC end/failed describes settlement of the official client-port promise, which can happen after a local observation deadline has already suppressed delivery. A watcher wake indicates a reactive invalidation, not proof of visible text. These events do not expose Gateway HTTP internals or provider queue timing. See [performance measurement](../architecture/performance.mdx#latency-diagnostics) for backend and browser markers.

## Contracts and outcomes

`TextSubmitV1` accepts only new text parts, Agent selectors, optional conversation and a stable `clientRequestId`. Scope is server-resolved. `RuntimeRunHandle` pins actor/scope/run/conversation/definition identity but grants no access.

`RuntimeRun` exposes separate response, memory and graph status, context completeness and failure codes. `RuntimeObservation` includes retained sequenced parts, cursor and exact tool approvals. Canonical history is paginated.

`RuntimeMediaSubmit` retains a stable request, `image`/`video` kind, prompt and optional immutable input asset/conversation in its type contract. The qualified image path uses `kind: 'image'` and a text prompt without `inputAsset`. Its observed descriptor has `callbacks: false`; serving identity and USD charges remain unknown. Models/options/budgets are server policy.

The `video` kind, `media.video.generate` operation, video input and signed callback/native polling/provider-download contracts are reserved. Asynchronous video generation is unavailable in Convex Gateway, cannot be enabled for an individual team or deployment, and is explicitly deferred until official support and real qualification with independent acceptance. These retained methods and types do not imply a functional video capability. Existing video-file uploads and authenticated asset delivery remain in scope.

`getMediaJob` and `listMediaJobs` read retained state. `reconcileMediaJob` preserves the original job identity, can mark expired submissions unknown and can resume eligible retained-output recovery; it does not blindly generate again or guarantee recovery of a lost upstream image result. Native polling/download and missed-callback recovery describe the future video path. `ContentSubmitV1` accepts a closed intent and version-bound sources.

Defaults are 10 seconds for authentication and 12 seconds for RPC observation. `CortexRuntimeError` includes `code` and outcome classification. Uncertain issued mutations are recovered by their original identity, never blindly retried as new work. Clear private views on authority loss and close owned clients/previews.

The unreleased SDK 0.39 candidate adds a cancellable HTTP session check during a pending owned or official-client handshake. Only an authoritative401 or structured `UNAUTHENTICATED` refusal can end a silent WebSocket wait. HTTP success cannot authenticate the client; official WebSocket acceptance and the original fresh session/delivery checks remain required. Custom borrowed transports enable the refusal check by supplying the standard `fetch` option. Refresh, token replacement, timeout and close discard late probe results. Controlled tests and fresh native owner/expired/invalid-signature checks passed. The signed negatives returned `UNAUTHENTICATED` in 133/89 ms with no protected data and unchanged data/financial inventories; these observed timings are not a guarantee. Historical WebSocket timeout failures remain recorded.
