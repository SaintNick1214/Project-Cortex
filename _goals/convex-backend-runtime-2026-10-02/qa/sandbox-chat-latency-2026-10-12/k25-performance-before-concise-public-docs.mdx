# Performance and limits

Cortex separates user-visible response completion from asynchronous memory/graph completion and optional conversation-title work. This avoids coupling response latency to every indexing stage while retaining explicit consistency controls.

## Bounded work

Published policy bounds input/context/output tokens, tool steps, timeout, budgets and concurrency. Retrieval and transcript reads are paginated/bounded. Strict barriers capture finite cutoffs and configured deadlines; a hole or unavailable stage is an explicit result.

Runtime client authentication defaults to 10,000 ms; RPC observation defaults to 12,000 ms, configurable within supported bounds. An issued mutation timeout reports uncertainty rather than cancellation/retry. Retain run/job identities for recovery.

Private upload/delivery is capped at 20,000,000 decoded bytes; providers can impose smaller input limits. Reconnect snapshots retain bounded references rather than copying assets or upstream responses into browser persistence. Asynchronous video generation remains deferred because the official Convex AI Gateway does not support it.

Selected native queries and mutations reuse raw principal, membership, grant, scope and tombstone records within one atomic invocation. Every authorization predicate still runs, returned records are detached, and database or child-mutation writes invalidate the retained reads. The next invocation reads current records again. Source retrieval, final memory delivery and private output observation retain their original read paths. This scope does not retain permissions, model decisions or authority across a network call or process lifetime.

Empty-context preparation can also reuse raw deployment-policy and qualification rows within its own transaction. It fetches that metadata again before saving context, and every original policy, qualification and profile check still runs. This reuse does not cross transactions or replace source and delivery checks.

Selected model-preparation parents also reuse exact raw official Agent message-ID lookups within one invocation. Canonical transcript, current source and authorization checks still run; writes invalidate retained results, and fresh save fences clear them. The installed hosted candidate passed functional qualification, but this does not establish a subsecond response or a controlled speed improvement.

Fresh installations store compact versioned references to the trusted compiled manifest. New accounts inherit the validated installed root. Existing full records remain supported without rewriting their data or financial history. The runtime still reads and validates current controls. Final memory delivery also shares profile and run-budget initialization for vectors with identical complete profiles and budget identities within one transaction; each vector retains its own authorization, source, chunk, receipt, hash and expiry checks. These changes require hosted measurements before reporting latency improvements.

## Latency diagnostics

Diagnostics are opt-in and contain fixed scalar metadata rather than prompts, output, credentials or raw errors. Enable each flag in the process that owns its clock:

| Surface | Enablement | Observable boundary |
| --- | --- | --- |
| SDK | `onLatencyEvent` client option | Auth begin/ready/denied, per-RPC begin/end/failed with method/duration, and watcher wake. |
| Backend | `CORTEX_RUNTIME_LATENCY_TRACE=1` | Native claim, context retrieval, model-policy, Gateway acquisition/processed-part/text and finalization phase metadata. |
| Basic CLI | `CORTEX_RUNTIME_LATENCY_TRACE=1` in the CLI process | SDK events plus submit begin and first non-whitespace answer write acknowledged by stdout. |
| Vercel quickstart | `NEXT_PUBLIC_CORTEX_LATENCY_TRACE=1` in the app environment | SDK events plus submission, admission delivery, first-text DOM commit, after-paint marker, response-status DOM commit, canonical-answer completion DOM commit and transport completion. |

The SDK's [`RuntimeLatencyEvent`](../api-reference/runtime-client.mdx#opt-in-client-latency-events) includes version, phase, atMs and optional rpcId/method/durationMs. Pair events within the same client clock. Backend timestamps and browser/CLI clocks have different origins; do not subtract their absolute timestamps to invent an end-to-end duration. RPC settlement may occur after a local deadline, and a watcher wake does not imply that text was painted.

Workflow's deterministic handlers disable `process`, so tracing safely defaults off inside those handlers. Use the actual Workflow journal's step start/completion metadata for memory barriers, context preparation, model steps and title enqueue. Native mutations also keep `Date.now()` fixed within one transaction; a zero timestamp difference there does not prove zero execution time. Opt-in native mutation spans use `performance.now()` to measure admission submission, start, final read, run claim and Workflow startup. Match their native execution/request identities; the submission span uses a fixed correlation label because the run does not yet exist. Inclusive start contains claim and Workflow startup, so do not add those nested durations again. Missing or invalid durations remain unavailable.

Hosted Convex is the primary latency measurement environment. Run the canonical clients against a verified disposable cloud database and label the conditions. Docker can host those clients while the backend remains hosted; a local Convex benchmark is separate evidence.

The quickstart records first-text DOM commit from React's layout phase and schedules its after-paint marker with two animation frames, retaining document visibility metadata. The quickstart separately records `response.status.dom-commit`, `transport.complete` and `answer.complete.dom-commit`; canonical answer completion waits for the matching transported assistant message to be committed. Distinguish those markers from the first durable backend part and the first processed native stream text. The CLI's stdout acknowledgement is a separate boundary from a browser paint. Measure submission-to-visible text in the actual foreground application and report the selected boundary explicitly.

The official Gateway provider internally acquires its service token and makes its HTTP request without exposing those subphase hooks. Native stream acquisition combines that opaque work. Processed-part/text markers are not raw network-first-byte measurements and do not reveal OpenAI internal queue timing.

## Measure the right states

Observe response, memory and graph latency separately. Use current profile metadata, contiguous watermark holes and durable job state to explain waiting. Configure graph only when needed and keep graph credentials in the worker service.

No universal throughput or latency guarantee follows from a source build. Capacity depends on deployment, qualified model bounds, workload and external services. See [memory orchestration](../core-features/memory-orchestration.mdx) and [model policy](./model-policy.mdx).
