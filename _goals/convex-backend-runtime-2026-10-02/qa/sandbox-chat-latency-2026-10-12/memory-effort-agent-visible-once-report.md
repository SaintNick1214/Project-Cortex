# Private V8 repeated visibility ACK — rejected without a product edit

The successful-first-ACK shortcut does not preserve every current visible-effect fence. All11 frozen ef094 product/test hashes still match the accepted combined manifest. No product/test edits, test runs, services, models, builds, deployments or Git commands were performed for this diagnosis. This is source/control-flow evidence, not a new runtime test or hosted timing claim.

The concrete counterexample is financial-only cancellation between chunks:

1. The first exact private V8 native attempt's `markVisible` succeeds; its first text A can publish.
2. Existing `runtimeModelPolicy:cancelBudget` sets the financial run account's `cancelled=true`/version+1 (`runtimeModelPolicy.ts:1285–1290`). It does not cancel the Core runtimeRuns/outbox/lease or change grant/source/definition state.
3. The current next-chunk path invokes `markVisible` again. `currentOperation` rejects that cancelled account (`runtimeModelPolicy.ts:317–324`) before Gateway enqueues chunk B (`runtimeGateway.ts:1026–1030`).
4. If a private wrapper instead returns the first ACK, chunk B reaches the Agent pipeline. Original `recordOutput` runs `executionContext`, validates tools and writes parts (`runtimeAgent.ts:1007–1015`). Those reads have no native financial attempt/operation/account check; this financial-only cancellation is invisible to them. `guardedObservation` also has no such financial check (`runtimeAgent.ts:1691–1734`). A still-authorized reader/session can receive B.

The original `recordOutput` does indirectly revalidate executable-definition policies through `currentRun→readCurrentExecutableDefinition→narrowPolicies`. That does not duplicate `currentOperation`'s exact native operation/attempt state, financial cancellation, parent lineage, pinned-model/qualification/evidence compatibility or tenant override actor checks. Treating the first ACK as a reusable authorization decision would remove these later checks. Native `markVisible` already avoids a financial write when the monotone bits have not changed; most repeated work is current fencing, not repeated bit updates (`runtimeModelPolicy.ts:854–867`).

The official stream topology also prevents assuming `onChunk` is a downstream barrier. AI SDK7 enqueues before awaiting its onChunk notification (`node_modules/ai/src/generate-text/stream-text.ts:1495–1508`). Official Agent consumes its UI stream into DeltaStreamer/component storage (`@convex-dev/agent/src/vercel/client/streamText.ts:280–303`, streaming.ts:377–385). The audited SDK runtime/client does not export raw component syncStreams/listDeltas delivery; browser transport uses guarded `watchObservation`. This is not a claim that an existing raw-client bypass exists. It establishes that callback completion cannot be assumed to precede every downstream component chunk. Agent public publication batches after the first text, so a later callback does not necessarily issue a fresh recordOutput for that exact chunk (`runtimeAgent.ts:1137–1181`).

Server tools have no execute callbacks (`runtimeAgentTools.ts:35–44`); complete tool requests/effects and next model admission retain their own guards. They cannot protect earlier text already published. A first tool-input ACK also cannot stand in for a later outputVisible bit transition without preserving the original separate evidence; premarking all bits would change abort-after-ACK state.

No deduplication was implemented. The first ACK-before-emit order, abort-after-ACK zero-output outcome, every later markVisible invocation, durable text/tool guards, deadlines, original financial UNKNOWN/replay/fallback semantics and JWT verification remain unchanged. A safe future composition would need the exact missing native attempt/currentOperation predicates at each actual publication boundary and a proved downstream/component order. That is a different guard-relocation change, not an ACK cache; this report does not authorize or implement it.

Exact inspected references and the unchanged baseline hash check are recorded in `memory-effort-agent-visible-once-report.json` and `memory-effort-agent-visible-once-source-hashes.json`. The observed failed-tool timings supplied by Root motivated this audit; no speed saving is inferred.
