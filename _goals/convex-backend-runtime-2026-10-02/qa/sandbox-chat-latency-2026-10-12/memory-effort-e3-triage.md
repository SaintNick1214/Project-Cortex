# Bounded E3 triage

Read-only triage of frozen E1/E2 source, `modified-goal-execution-v4.md`, `memory-effort-e1-report.md`, `memory-effort-e2-report.md`, and saved K29 critical paths. No tests, services, inference, or product edits. Fast/Normal/High/Max hosted targets are **3/6/8/30 seconds**; the new effort profiles have no actual qualification measurements yet. K29 is a pre-effort baseline, not profile qualification or proof of causality.

1. **Compose public recall read and final validation in one native invocation.** `convex-dev/runtimeMemoryQuery.ts:157–168` currently awaits `prepareReads`, ANN, `readMatches`, then a separate `finalRecallDelivery` mutation; only synchronous ranking separates the last two calls (`runtimeMemoryServices.ts:150–166`). Mirror the existing Agent `readMatchesAndDeliveryV8Handler` pattern (`runtimeAgentRecall.ts:185–224`): execute read plus the complete final predicate in one native mutation, and defer bounded delivery refusal until the original Action delivery stage. Retain fresh raw source/bridge reads for final validation, canonical payload checks, final unscoped authority, and the real Action-clock expiry/deadline checks after the RPC returns. Do not reuse an authority verdict across ANN or any other I/O. This targets the public post-attachment read/delivery tail: **701.81 ms** in K29, including `readMatches` **187.42 ms**, final delivery **215.51 ms**, and the intervening ranking/dispatch gap **3.58 ms**. Those spans are the affected region, not removable savings: final validation remains necessary. Benefit is one native dispatch boundary and potentially shared tentative snapshot control reads. Agent V8 already has this composition, so this is a public-recall improvement and must not be claimed as a new CLI chat improvement.

2. **If new profiles show final validation is material, overlap only independent exact-row lookups within that final native snapshot.** `ConvexMemoryRepository.checkDelivery` (`convex-dev/runtimeMemoryRepository.ts:359–408`) awaits each fact lookup at 370–371 and vector lookup at 390–391 in serial loops. After the existing initial read-authority check, prefetch bounded batches of those pure, scope-indexed lookups; join settled results, then consume them in the original source → fact → vector and per-item order. Keep per-resource authorization, source/current ancestry validation, profile checks, canonical hashes, deadline collection, and final raw authority checks in their existing validation order. Do not parallelize the whole stateful loops or share mutable deadline/profile sets concurrently. Preserve the byte/entry envelopes, bound concurrency, and retain deterministic failure precedence; no returned result may depend on an unjoined task. This applies to public and Agent final validation. K29 public final delivery was **215.51 ms**, with 70 reported document reads / 315,922 bytes; Agent combined read/delivery engine spans were **322.5/479.7 ms** inside CLI post-attachment tails **595/747 ms**. These measurements include other required work and repeated reads, so they do not isolate row-wait cost or justify a promised saving. Prefer this small change only if actual profile spans still identify this pass as a hotspot.

Focused outcome checks for either selected change: identical ranked items, source attribution, bridge bindings, effort trace and failure precedence; revocation/source edits/tombstones/profile drift after ANN still refuse; denied or changed intermediate bridges still refuse; actual expiry or retrieval deadline crossing while the final RPC returns still refuses/drops optional evidence as before. For lookup overlap, inject competing failures and delayed reads to prove original error ordering, bounded concurrency, all tasks joined, and no late output. Retain existing replay/unknown-cost outcomes and separate financial evidence capture and result-attachment commits. No extra paid attempts, app loop, model substitution, or cross-I/O authorization cache.

Already present and not E3 work: public vector/fact branches use `Promise.allSettled` (`runtimeMemoryQuery.ts:115–137`); Agent V8 already composes final read/delivery. K29 first text → durable output took roughly 415–552 ms, but its visibility/output predicates are not interchangeable with removable pure reads. No proposal here removes those guards. K29 recall was 1.842/2.111 seconds for the CLI pair; the historical eight-second recall delay did not persist. Four unequal contexts cannot attribute the client first-visible differences (browser 3.960/3.580 seconds, CLI 6.855/6.981 seconds) to one source change. Embedding variability is not evidence for a cache or model change.
