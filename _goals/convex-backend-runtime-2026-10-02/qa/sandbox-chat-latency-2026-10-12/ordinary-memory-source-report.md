This report does not establish native behavior or a latency result.

Ordinary `cortex.memory.remember(exchange)` now invokes one authenticated canonical backend capture between fresh SDK session checks. Typed `CortexRuntimeClient.remember` and `rememberStatus` use the same registration. A capture creates two official Agent messages, their existing canonical transcript/source/ingestion records, and one scoped trace metadata row per message. The supplied assistant text is external `assistant_claim` content; it is not model/tool evidence. The durable result returns real message/source event IDs, revision, selected profile and current stage status. Convenience results contain empty derived arrays while indexing is pending. No caller model, embedding, fact writer, graph loop, automatic retry or legacy migration runs.

An explicit request ID replays an identical capture once and rejects changed input. The convenience API generates a fresh ID for every invocation, including identical text, and returns that ID on an uncertain error for explicit recovery. A fresh capture-owned conversation retains its original manual edit lock and uses an explicit separate append ingress marker. Repeated captures append under fresh verified-owner/write-grant and epoch checks. Administrator capture locks deny new appends and exact replay; independent authorized read-only status remains available. Existing Agent conversations cannot gain the marker through this endpoint, cannot bypass their manual lock, and cannot silently gain approval. `setCaptureLock` is administrator-only. Actor user/participant labels are bound to the verified identity. Metadata is plain bounded JSON; unsupported inference/functions/options refuse before dispatch.

The additive capture tables are `runtimeMemoryCaptureConversations`, `runtimeMemoryCaptures` and `runtimeMemoryCaptureMessages`. The private idempotency record stores the normalized request; trace rows contain attribution/metadata and native source bindings. Original transcript deletion/edit/tombstone and source/profile/current-authority checks still fence receipt projection and replay. This batch does not add a legacy migration or claim physical erasure of retained ledger metadata.

Public `runtimeMemory.recall` retains original authority and committed budget creation, then replaces the original readiness/preparation/profile/two-resolution RPC sequence with one internal native query. It runs those original validators in their original memory order within that snapshot. Initial readiness errors keep their original not-dispatched control envelope; later preparation errors retain the uncertain functional envelope. Returned profiles/resolutions are proposals. A separate fresh native parent re-derives the exact request/account/profile binding and invokes original `admitHandler`, followed by the original registered checkpoint child. A caught checkpoint refusal retains the parent's reservation and rolls back only the child; the Action rethrows without dispatch. Capture, financial settlement, attachment, vector search and the shared original post-embedding recall tail remain separate. No second funding, retry, policy decision cache or cross-RPC authority reuse was introduced. The public query's pure refusal codec was extracted unchanged to remove unnecessary memory-to-Agent module coupling; Agent retains its original exports.

Final delivery uses the existing invocation-local raw authority scope for the read-only original consumed-row loop, then calls its original last `deliveryExpiresAt`/authority/grant fence on the **unscoped original context**. All source/fact/vector/profile/hash/deadline checks and their order remain. The actual-handler three-source fixture produced the same result/state and 34 non-auth read/write entries while authority reads fell from 223 to 37. This controlled count is not a cloud document count or a speed claim. Original last-chunk revocation, expiry, stale-source and observation-sensitive denials remain intact.
