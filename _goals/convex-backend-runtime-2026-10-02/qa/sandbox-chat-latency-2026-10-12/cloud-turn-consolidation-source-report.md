## Changed commit and recovery boundaries

Composition deliberately changes pre-dispatch rollback points. If an empty-path resolution fails, its newly grouped context save and model-operation start roll back together. Existing barrier-started state and original interruption handling remain explicit. A populated Action can already have committed context before later model preparation fails; the grouped operation start then rolls back, so interruption may classify that pre-dispatch failure as FAILED rather than the former started-operation UNKNOWN. Neither path issued a provider permit or incurred new model liability. After checkpoint, the original UNKNOWN/reservation/no-replay behavior is unchanged. Late reserve/bind faults roll the full account/permit parent back.

A duplicate ordinal-zero Action after canonical context is committed retains the original routed-context INVALID_STATE denial. It does not infer again. The Action tests prove the actual original authenticated reconciliation path recovers a genuine saved generation after the component/Core-finish gap or completed-operation/finalize gap, producing one final transcript and ingestion registration. Stale transcript completion is refused. This is explicit safe recovery rather than automatic Action retry.
