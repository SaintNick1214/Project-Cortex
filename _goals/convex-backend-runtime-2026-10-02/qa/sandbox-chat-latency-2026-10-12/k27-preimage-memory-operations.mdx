# Explicit Memory API

Use this namespace for independent memory ingestion, record search and maintenance. Runtime Agent turns already own their extraction/embedding pipeline; do not call `remember` or `rememberStream` to mirror a remote response. Local semantic/extraction callbacks belong to advanced explicit administration and do not bypass runtime model policy.

## Usage boundary

Access the namespace on an explicitly configured root `Cortex` client. Host JWT and deployment-operator transports are distinct; validate current resource scope and do not infer authority from `AuthContext` metadata. See [administrative operations](../security/admin-operations.mdx).

## Remember, search and validation

In the new local candidate, ordinary authenticated `cortex.memory.remember(params)` submits one backend-owned canonical exchange capture. The backend stores a separate row per message and schedules memory asynchronously. The result has `conversation` and a `durable` receipt; `memories` and `facts` are initially empty, so inspect the receipt's indexing status or use [`rememberStatus`](runtime-client.mdx#capture-an-external-exchange). The latest disposable cloud scenario passed distinct repeated captures, exact replay, canonical provenance, contiguous facts/vectors, public recall and access/lock/deletion/revocation negatives. Earlier failures remain recorded. The subsequent candidate also passed all four ordinary chat memory outcomes; the latency target remains unresolved; see [measured outcomes](../architecture/performance.mdx#latency-diagnostics).

An optional caller-supplied `requestId` provides exact replay. Without one, each invocation generates a new identity, including identical exchanges at different points in a conversation. Retain an explicit identity for recovery; an uncertain capture error carries the generated request ID when applicable. `participantId`, ownership labels and metadata remain subject to verified grants. The ordinary path accepts no local extraction/embedding callbacks or processing-policy overrides; unsupported options receive `CAPABILITY_UNAVAILABLE` before dispatch.

Explicit deployment-operator orchestration remains a separate historical administrative contract. The options, synchronous layer results and local callbacks described below apply to that operator path. They do not describe ordinary backend capture and cannot bypass runtime model policy. For ordinary application chat, use the remote runtime, which already owns canonical capture and indexing.

Supply a nonempty `conversationId`, `userMessage` and `agentResponse`. At least one of `userId` or `agentId` must own the exchange; `userName` is required when `userId` is present. `participantId` records the contributing participant. An omitted `memorySpaceId` uses `"default"` with a warning; explicit space IDs are preferable for administration. `importance` is 0–100; tags must be nonempty strings. Missing required fields raise `MemoryValidationError` with `code: MISSING_REQUIRED_FIELD` and `field`; missing ownership uses `OWNER_REQUIRED`; invalid importance uses `INVALID_IMPORTANCE`.

`RememberOptions.extractFacts` defaults to false. Extraction and embedding callbacks are advanced local processing supplied by the operator. `factDeduplication` defaults to semantic matching with structural fallback when no embedding callback is configured. Belief revision can be disabled with `beliefRevision: false`; when enabled it records ADD/UPDATE/SUPERSEDE/NONE actions in `factRevisions`. `RememberResult.conversation` identifies the stored exchange; `memories` and `facts` contain the resulting records. Do not infer that a nonempty response guarantees every downstream layer completed.

`search` returns `MemoryEntry[]` normally and `EnrichedMemory[]` with `enrichConversation: true`. Enrichment wraps each memory in `memory` and adds available `conversation`, `sourceMessages` and `facts`; those related records are optional. `get` returns null when the memory is absent and uses the same wrapper when `includeConversation: true`. Explicit search embeddings must be nonempty arrays of finite numbers and match the configured profile dimension. `minScore` is 0–1, `minImportance` is 0–100. A configured local embedding generator makes automatic search embedding an operator capability; generation failure falls back to text search. Use the remote `recall` endpoint for ordinary application retrieval under runtime policy.

```ts
import type { Cortex } from '@cortexmemory/sdk';

export async function ingestApprovedExchange(cortex: Cortex, spaceId: string) {
  const result = await cortex.memory.remember({
    memorySpaceId: spaceId,
    conversationId: 'admin-import-001',
    userId: 'user-123',
    userName: 'Alex',
    userMessage: 'My preferred delivery window is Tuesday morning.',
    agentResponse: 'I recorded Tuesday morning as your preference.',
    importance: 70,
    tags: ['delivery'],
  }, { extractFacts: false, beliefRevision: false });
  return { conversationId: result.conversation.conversationId,
    memoryIds: result.memories.map(memory => memory.memoryId) };
}

export async function searchApprovedMemory(cortex: Cortex, spaceId: string) {
  const results = await cortex.memory.search(spaceId, 'delivery', {
    userId: 'user-123', limit: 10, minImportance: 50,
    enrichConversation: true,
  });
  return results.map(result => ({ id: result.memory.memoryId,
    text: result.memory.content, sourceMessages: result.sourceMessages ?? [] }));
}
```

`forget` removes the vector memory and associated facts. Without `deleteConversation`, the ACID conversation is preserved and `restorable` is true. `deleteEntireConversation: true` with `deleteConversation: true` deletes the whole referenced conversation. The individual-message branch currently reports referenced message count without deleting those messages; do not use it as a user erasure guarantee. Missing memory raises `MEMORY_NOT_FOUND`. Use the [supported user erasure workflow](user-operations.mdx#supported-erasure-and-receipts) for an administrative deletion request.

`recall` returns ranked/deduplicated `items`, `sources`, `totalResults`, `queryTimeMs`, `graphExpansionApplied` and optional formatted `context`. Per-call limits override configured/environment defaults: memories 20, facts 15, graph hops 2, entities per hop 5, results per entity 3 and total 30. `graphHops: 0` disables expansion. These explicit recall limits are separate from runtime Agent context policy.

## Version and bulk operation outcomes

`getVersion` and `getAtTimestamp` return null when no matching retained version exists. `getHistory` returns version/content/optional embedding/timestamp entries. `update` requires at least one content/embedding/importance/tags change. `delete`, `deleteMany` and `archive` may report `DomainPartial`; inspect exact physical outcomes before continuing. Archive intents identify the selected resource and mutation identity; preserve them across recovery. Exports return serialized `data`, format, count and export timestamp rather than writing a file for you.

The retained `autoEmbed`/`autoSummarize` flags do not provision a hosted embedding or summarization service. Current explicit processing uses supported configured/local callbacks; runtime processing uses backend policy.

## Operator parameters and result contracts {#parameter-and-result-contracts}

These are reference definitions for the explicit operator APIs. Ordinary capture accepts the limited fields described above and checks existing verified scope; it does not auto-register grants, users or spaces. Optional fields use `?`; timestamps are milliseconds since epoch unless an operation accepts a `Date`. Resource identifiers and participant metadata do not grant runtime authority.

### `RememberParams`

```text
export interface RememberParams {
  requestId?: string;
  expectedRevision?: number;
  memorySpaceId?: string;
  tenantId?: string;
  conversationId: string;
  userMessage: string;
  agentResponse: string;
  userId?: string;
  agentId?: string;
  userName?: string;
  participantId?: string;
  skipLayers?: SkippableLayer[];
  extractContent?: (
    userMessage: string,
    agentResponse: string,
  ) => Promise<string | null>;
  generateEmbedding?: (content: string) => Promise<number[] | null>;
  extractFacts?: (
    userMessage: string,
    agentResponse: string,
  ) => Promise<Array<{
    fact: string;
    factType:
      | "preference"
      | "identity"
      | "knowledge"
      | "relationship"
      | "event"
      | "observation"
      | "custom";
    subject?: string;
    predicate?: string;
    object?: string;
    confidence: number;
    tags?: string[];
  }> | null>;
  autoEmbed?: boolean;
  autoSummarize?: boolean;
  importance?: number;
  tags?: string[];
  factDeduplication?: "semantic" | "structural" | "exact" | false;
  observer?: OrchestrationObserver;
}
```

| Field | Meaning and defaults |
| --- | --- |
| `memorySpaceId` | Memory space for isolation. If not provided, defaults to 'default' with a warning. Auto-registers the memory space if it doesn't exist. |
| `tenantId` | Multi-tenancy: SaaS platform isolation. When provided, all data is scoped to this tenant. Note: If using authContext, tenantId is auto-injected unless explicitly provided here. |
| `conversationId` | Conversation ID. Required. |
| `userMessage` | The user's message content. Required. |
| `agentResponse` | The agent's response content. Required. |
| `userId` | User ID for user-owned memories. At least one of userId or agentId is required. Auto-creates user profile if it doesn't exist (unless 'users' is in skipLayers). |
| `agentId` | Agent ID for agent-owned memories. At least one of userId or agentId is required. Auto-registers agent if it doesn't exist (unless 'agents' is in skipLayers). |
| `userName` | Display name for the user (used in conversation tracking). Required when userId is provided. |
| `participantId` | Participant ID for Hive Mode tracking. This tracks WHO stored the memory within a shared memory space, distinct from userId/agentId which indicates ownership. |
| `skipLayers` | Layers to explicitly skip during orchestration. By default, all configured layers are enabled. |
| `factDeduplication` | Fact deduplication strategy. Defaults to 'semantic' for maximum effectiveness. - 'semantic': Embedding-based similarity (most accurate, requires generateEmbedding) - 'structural': Subject + predicate + object match (fast, good accuracy) - 'exact': Normalized text match (fastest, lowest accuracy) - false: Disable deduplication (previous behavior) The generateEmbedding function (if provided) is automatically reused for semantic matching. |
| `observer` | Observer for real-time orchestration monitoring. Provides callbacks for tracking layer-by-layer progress during the remember() orchestration flow. Integration-agnostic. |

| Field | Meaning and defaults |

| `total` | Final aggregate limit on total results returned. Applied after merge, dedupe, and ranking. Env: CORTEX_RECALL_LIMIT_TOTAL Default: 30 |

## Errors and lifecycle

Validation, missing capability, authorization, stale version and partial/unknown committed outcomes are explicit. Inspect operation/write/deletion receipts before recovery; do not repeat an external effect under a new identity after uncertainty. Close owned clients and graph resources at the end of the server workflow.

See [runtime client](./runtime-client.mdx) for ordinary app execution and [error handling](../reference/error-handling.mdx) for recovery boundaries.
