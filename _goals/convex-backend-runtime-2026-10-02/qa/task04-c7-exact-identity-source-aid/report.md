## Observed defect and limits

C6 `preimage-store.mjs:10` obtains Number Stats and compares eight fields: dev, ino, mode, uid, size, mtimeMs, ctimeMs, nlink. It omits gid and uses floating millisecond timestamps. It therefore supplies neither all nine exact integer identity fields nor exact timestamp equality. Native default Stats returning Numbers is legitimate outward API behavior; using those Numbers as internal exact identity authority is the defect.

The independent own data control reproduces the reviewer's decimal example: exact inode9223372036855902365 and adjacent9223372036855902366 both convert to Node Number/JSON decimal9223372036855902000. This decimal display is itself Number formatting; it does not identify the original integer. Converting that Number through String or BigInt cannot restore its source integer. Equal bytes/SHA256 do not distinguish different filesystem objects. A later exact capture, current Python full literal seal or current source preservation does not repair already rounded historical records or establish their earlier identities.

Copied frozen `sourcepins.json` uses actual current schema `W`, not the older `rows` schema. Its128 W entries have safely representable current dev/ino/mode/uid/gid/nlink/size, but every mtime_ns/ctime_ns exceeds2^53−1. These are observations of copied frozen pin data, not a general precision contract for those fields and not a new read of all public/native objects. The first own range-analysis schema assumption failed KeyError rows; the failure is retained separately, then the actual schema was inspected and analysis corrected. No candidate execution occurred.

`package-aliases.mjs:3` already uses JSON.parse reviver source tokens for mtime_ns and ctime_ns only. `:4–5` uses BigInt native stats and decimal strings for current values, but its `same()` coerces arbitrary expected values with String and iterates only keys supplied by expected. Unsafe dev/ino or other integer JSON tokens have rounded before that String operation. Empty/incomplete expected identity can vacuously pass the identity predicate. The eight-field alias writer also omits gid. This does not prove current aliases had unsafe dev/ino; it demonstrates an incomplete general contract and missing schema validation.

Compiler tape/artifact ports already retain BigInt dev/ino for their internal held descriptors. `recorded-esbuild.mjs:11` stores those exact pins as strings; `:17` then compares String(Number snapshot dev/ino) against them. A filesystem with unsafe inode values may produce a false reject or loss of exact identity elsewhere. Converting all serialized fields to strings without updating uid/mode checks at that same line would also break comparisons/bitwise logic. Do not perform an unchecked broad text replacement.

Process startTime is currently a raw `/proc` decimal token string in `owned-group.mjs:3`, `preimage-store.mjs:6`, and ROOT owner/recorder fields in `root-launcher.mjs:10`. No observed starttime Number conversion appears at these sites. PID/PPID/PGID are converted to Number and ordinarily kernel-bounded safe values; future parsing must validate their decimal syntax and exact safe integer bounds before using Node process APIs. Preserve startTime as an exact decimal string and reject numeric startTime inputs rather than introducing a new conversion. Compiler service events contain native PID Numbers; retain safe validation, and do not infer that recording PID alone is full process lifetime identity. The aid did not inspect live service PIDs or dispatch a service.
